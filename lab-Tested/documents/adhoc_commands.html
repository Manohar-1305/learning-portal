Ansible Ad Hoc Commands

1. What are Ansible Ad Hoc Commands?

Ansible ad hoc commands allow you to execute simple tasks on managed nodes directly from the Ansible controller without creating a playbook. They are useful for quick operations such as checking connectivity, gathering system information, managing services, installing packages, and copying files.

Command Syntax 
ansible <host-pattern> -m <module> -a "<arguments>"

2. Test Connectivity Using Ping

The ping module checks whether Ansible can connect to managed hosts and execute Python-based Ansible modules. It does not send an ICMP network ping.

Check all managed hosts 
ansible all -m ping
Check a specific host 
ansible ansible-client -m ping

3. Execute Commands on All Hosts

Use the command module to execute a command on managed hosts. The command module does not process shell operators such as pipes, redirection, or command chaining.

Check hostname 
ansible all -m command -a "hostname"
Check current date 
ansible all -m command -a "date"
Check uptime 
ansible all -m command -a "uptime"

4. Execute Shell Commands

The shell module executes commands through the remote host's shell. Use it when you need shell features such as pipes, redirection, environment variables, or command chaining.

Check running processes 
ansible all -m shell -a "ps aux | head"
Check disk usage 
ansible all -m shell -a "df -h"

5. Gather System Information

The setup module collects facts about managed hosts, including operating system details, memory, CPU, network interfaces, IP addresses, and hardware information.

Gather all facts 
ansible all -m setup
Gather operating system information 
ansible all -m setup -a "filter=ansible_distribution*"
Gather memory information 
ansible all -m setup -a "filter=ansible_memory_mb"

6. Create Directories

The file module manages files and directories on remote hosts. Use the state=directory parameter to create a directory.

Create a directory 
ansible all -m file -a "path=/opt/ansible-demo state=directory"

7. Create Files

Use the file module with state=touch to create an empty file. If the file already exists, Ansible updates its timestamps.

Create a file 
ansible all -m file -a "path=/tmp/ansible-demo.txt state=touch"

8. Copy Files to Managed Hosts

The copy module transfers files from the Ansible controller to managed hosts. The destination directory must exist or be creatable by the remote user.

Copy a file 
ansible all -m copy -a "src=/tmp/demo.txt dest=/tmp/demo.txt"
Copy content directly 
ansible all -m copy -a "content='Hello from Ansible' dest=/tmp/hello.txt"

9. Install Packages

The apt module manages packages on Debian-based systems such as Ubuntu. Use become to execute package-management operations with elevated privileges.

Update package cache 
ansible all -b -m apt -a "update_cache=yes"
Install Nginx 
ansible all -b -m apt -a "name=nginx state=present"
Remove Nginx 
ansible all -b -m apt -a "name=nginx state=absent"

10. Manage Services

The service module manages services on remote hosts. You can start, stop, restart, and enable services using ad hoc commands.

Start Nginx 
ansible all -b -m service -a "name=nginx state=started"
Stop Nginx 
ansible all -b -m service -a "name=nginx state=stopped"
Restart Nginx 
ansible all -b -m service -a "name=nginx state=restarted"
Enable Nginx at boot 
ansible all -b -m service -a "name=nginx enabled=yes"

11. Execute Commands on a Specific Inventory Group

Ansible inventory groups allow you to target a collection of hosts instead of executing commands against every managed host.

Execute against the clients group 
ansible clients -m ping
Check uptime for the clients group 
ansible clients -m command -a "uptime"

12. Use a Custom Inventory File

The -i option specifies an inventory file. This is useful when you want to execute commands using an inventory other than the default configured inventory.

Specify an inventory file 
ansible all -i inventory.ini -m ping

13. Specify a Remote User

The -u option specifies the SSH user Ansible should use when connecting to managed hosts.

Connect using a specific user 
ansible all -u ubuntu -m ping

14. Execute Commands with Elevated Privileges

The -b option enables privilege escalation (become). It is commonly used for operations that require root permissions, such as installing packages or managing system services.

Execute a command as root 
ansible all -b -m command -a "whoami"
Use sudo password prompting 
ansible all -b -K -m command -a "whoami"

15. Check Ansible Inventory

The ansible-inventory command displays the hosts and groups defined in your inventory configuration.

Display inventory 
ansible-inventory --list
Display inventory graph 
ansible-inventory --graph

16. Limit Execution to a Specific Host

The --limit option restricts command execution to a specific host or a subset of hosts matching the supplied pattern.

Run against one host 
ansible all --limit ansible-client -m ping

17. Check Ansible Version

Use the version command to check the installed Ansible version and configuration details on the controller.

Check Ansible version 
ansible --version

18. General Ad Hoc Command Syntax

The following syntax summarizes the commonly used options in Ansible ad hoc commands.

General Syntax 
ansible <host-pattern> \
  -i <inventory-file> \
  -u <remote-user> \
  -b \
  -m <module> \
  -a "<module-arguments>"
Important: Ad hoc commands are intended for quick, one-time operations. For repeatable tasks, multi-step automation, configuration management, and complex workflows, use Ansible Playbooks.
