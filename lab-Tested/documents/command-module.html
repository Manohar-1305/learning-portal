Ansible Command Module

The ansible.builtin.command module executes a command directly on a managed host without invoking a shell. Shell features such as pipes, redirection, variable expansion, and wildcard expansion are not processed by a shell.

In this lab, the Ansible controller runs commands against the managed host ansible-client. The examples assume that your inventory and SSH connection are already configured.

1. Execute a command

Use the command module to check the system uptime on ansible-client. The uptime command displays how long the system has been running, along with its load averages.

BASH — COMMAND
ansible ansible-client -m ansible.builtin.command -a 'uptime'

Explanation: The -m option specifies the Ansible module, and -a passes arguments to that module. Ansible connects to the managed host and executes uptime.

2. Check the hostname

Run the hostname command to identify the name of the managed host. This is useful for verifying that the command is running on the expected machine.

BASH — COMMAND
ansible ansible-client -m ansible.builtin.command -a 'hostname'

The output contains the hostname returned by the remote system.

3. List files in a directory

Use ls -la /tmp to display files and directories in /tmp, including hidden entries and detailed file information.

BASH — COMMAND
ansible ansible-client -m ansible.builtin.command -a 'ls -la /tmp'

The command module passes the command and its arguments directly for execution. It does not interpret shell operators or expand wildcards.

4. Create a playbook using vi

Instead of running commands individually, you can define them in a YAML playbook and execute multiple tasks in sequence. Use vi to create the playbook file on the Ansible controller.

BASH — CREATE THE PLAYBOOK
vi command-playbook.yml

When the editor opens, press i to enter Insert mode. Add the following YAML content:

YAML — command-playbook.yml
---
- name: Command module example
  hosts: ansible-client
  tasks:
    - name: Get hostname
      ansible.builtin.command:
        cmd: hostname
      register: hostname_output
      changed_when: false

    - name: Display hostname
      ansible.builtin.debug:
        var: hostname_output.stdout

Save the file by pressing Esc, typing :wq, and pressing Enter.

Explanation: The hosts field selects the managed host. The command task executes hostname, and register stores the task result in hostname_output. Setting changed_when: false prevents this read-only task from being reported as a change. The debug task displays the hostname from hostname_output.stdout.

5. Execute the playbook

Run the playbook from the directory where you saved it.

BASH — RUN THE PLAYBOOK
ansible-playbook command-playbook.yml

Ansible executes the hostname task on ansible-client and displays the captured hostname through the debug task.

6. Specify the working directory

The chdir parameter changes the working directory before the command runs. For example, use it to list the contents of /tmp without putting the directory path in the command.

Open the playbook for editing:

BASH — EDIT THE PLAYBOOK
vi command-playbook.yml

Press i and add the following task under the existing tasks: section, maintaining the same indentation as the other tasks:

YAML — TASK
    - name: List files in /tmp
      ansible.builtin.command:
        cmd: ls -la
        chdir: /tmp
      changed_when: false

Press Esc, type :wq, and press Enter to save the changes. Run the playbook again:

BASH — RUN THE PLAYBOOK
ansible-playbook command-playbook.yml

The command now executes with /tmp as its working directory. The changed_when: false setting is appropriate because listing files does not modify them.

7. Use creates to avoid repeated execution

The creates parameter tells Ansible to skip the command if the specified path already exists. This is useful for commands that should run only once when creating a marker file.

Open the playbook:

BASH — EDIT THE PLAYBOOK
vi command-playbook.yml

Press i and add this task under the existing tasks: section:

YAML — TASK
    - name: Create a marker file if it does not exist
      ansible.builtin.command:
        cmd: touch /tmp/ansible-marker
        creates: /tmp/ansible-marker

Save and exit using Esc, :wq, and Enter. Execute the playbook:

BASH — RUN THE PLAYBOOK
ansible-playbook command-playbook.yml

On the first run, Ansible creates /tmp/ansible-marker if the file does not exist. On subsequent runs, Ansible skips the command when that file is already present. This provides basic idempotent behavior for this example.

8. Useful vi commands

These are the essential vi commands for editing and saving Ansible playbooks:

VI — EDITOR SHORTCUTS
vi command-playbook.yml   # Open or create the file
i                         # Enter Insert mode
Esc                       # Return to Normal mode
:w                        # Save changes
:q                        # Quit if there are no unsaved changes
:wq                       # Save and quit
:q!                       # Quit without saving changes

9. Validate the playbook

Before executing a playbook, use syntax checking to detect YAML or Ansible playbook syntax errors.

BASH — SYNTAX CHECK
ansible-playbook --syntax-check command-playbook.yml

If the syntax check succeeds, execute the playbook:

BASH — EXECUTION
ansible-playbook command-playbook.yml
Important: Use ansible.builtin.command for simple commands that do not require shell functionality. Use ansible.builtin.shell when shell features such as pipes or redirection are necessary. Prefer purpose-built Ansible modules for managing files, packages, and services whenever suitable. When editing YAML with vi, preserve indentation because YAML uses indentation to define its structure.
