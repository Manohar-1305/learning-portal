Building Custom Ansible Modules Using Python

A step-by-step practical guide to developing, configuring, and executing a custom Ansible module on an Ubuntu virtual machine.

1. Introduction to Custom Ansible Modules

Ansible provides several built-in modules such as apt, yum, copy, file, service, user, and command. These modules help automate common system administration tasks.

However, there may be situations where the built-in modules do not provide the functionality required for a particular automation task.

In such scenarios, we can develop our own custom Ansible modules using Python.

A custom module allows us to implement our own logic and execute it through Ansible just like a normal built-in module.

What are we building?

We will create a Python-based custom module named ubuntu_system_info.

This module collects system information from an Ubuntu virtual machine and returns the results to the Ansible Controller.

2. Lab Architecture

We will use two Ubuntu virtual machines:

Machine Purpose
Ansible Controller Develop the Python module and execute the playbook.
Ansible Client Target machine where the custom module collects system information.
The Ansible Controller communicates with the Ansible Client over SSH. The client must have Python 3 available. The existing Ansible inventory and SSH configuration are assumed to be already configured.

3. Understanding the Custom Module Architecture

Before creating the module, understand how Ansible executes custom modules.

The execution flow is:

Ansible Controller | |-- Ansible Playbook | |-- Custom Python Module | |-- Ansible SSH Connection | v Ansible Client | |-- Execute Python Module |-- Collect System Information |-- Return JSON Result | v Ansible Controller | |-- Display Module Output

The custom module uses Ansible's AnsibleModule class. This class provides functionality for accepting arguments, handling errors, supporting check mode, and returning structured results.

4. Verify Ansible and Python Installation

Log in to the Ansible Controller and verify that Ansible is installed.

Ansible Controller

Verify Python 3:

Ansible Controller

Ansible Client

5. Create the Project Directory

We will create a dedicated directory for our custom module. All module files and the playbook will be maintained inside this directory.

Ansible Controller 
mkdir -p ~/ansible-custom-module/library

cd ~/ansible-custom-module

The library directory is important because Ansible automatically searches for custom modules in a library directory located alongside the playbook.

Expected Project Structure

ansible-custom-module/ | |-- library/ | | | |-- ubuntu_system_info.py | |-- ubuntu_system_info.yaml

6. Develop the Custom Python Module

Now we will create the actual Python module.

Module name: ubuntu_system_info

Python filename: ubuntu_system_info.py

Create the Python file using the following command:

Terminal 
cat > library/ubuntu_system_info.py <<'EOF'
#!/usr/bin/python3

from ansible.module_utils.basic import AnsibleModule
import platform
import socket
import shutil
import os
import subprocess


def get_memory():
    memory = {}

    with open("/proc/meminfo", "r") as file:
        for line in file:
            key, value = line.split(":", 1)

            if key in ["MemTotal", "MemAvailable"]:
                memory[key] = int(value.strip().split()[0]) // 1024

    return {
        "total_mb": memory.get("MemTotal", 0),
        "available_mb": memory.get("MemAvailable", 0)
    }


def get_disk():
    usage = shutil.disk_usage("/")

    return {
        "total_gb": round(usage.total / (1024 ** 3), 2),
        "used_gb": round(usage.used / (1024 ** 3), 2),
        "free_gb": round(usage.free / (1024 ** 3), 2)
    }


def get_ip():
    try:
        result = subprocess.check_output(
            ["hostname", "-I"],
            text=True
        )

        addresses = result.strip().split()

        return addresses[0] if addresses else "Unknown"

    except Exception:
        return "Unknown"


def get_os():
    os_info = {}

    with open("/etc/os-release", "r") as file:
        for line in file:
            if "=" in line:
                key, value = line.strip().split("=", 1)
                os_info[key] = value.strip('"')

    return {
        "name": os_info.get("NAME", "Unknown"),
        "version": os_info.get("VERSION_ID", "Unknown")
    }


def main():

    module = AnsibleModule(
        argument_spec={},
        supports_check_mode=True
    )

    try:

        system_info = {
            "hostname": socket.gethostname(),
            "os": get_os(),
            "kernel": platform.release(),
            "architecture": platform.machine(),
            "cpu_count": os.cpu_count(),
            "memory": get_memory(),
            "disk": get_disk(),
            "ip_address": get_ip()
        }

        module.exit_json(
            changed=False,
            system_info=system_info
        )

    except Exception as error:

        module.fail_json(
            msg="Failed to collect system information: {}".format(error)
        )


if __name__ == "__main__":
    main()
EOF

7. Understanding the Python Module Code

7.1 Import Required Libraries

We import Python libraries that help us collect information from the Ubuntu operating system.

7.2 Collect Memory Information

The get_memory() function reads the Linux file /proc/meminfo.

It extracts total memory and available memory and converts the values from KB to MB.

Python

Ubuntu maintains operating system information in /etc/os-release. We read this file to retrieve the OS name and version.

7.6 Initialize AnsibleModule

This is one of the most important components of a custom Ansible module.

Python 
module = AnsibleModule(
    argument_spec={},
    supports_check_mode=True
)

argument_spec: Defines the input parameters accepted by the custom module. In our example, the module does not require any input arguments.

supports_check_mode: Indicates that the module supports Ansible check mode. Since this module only collects information and does not modify the system, it can safely return information without making changes.

7.7 Return Module Results

Python 
module.exit_json(
    changed=False,
    system_info=system_info
)

exit_json() returns a successful result to Ansible in JSON format.

changed=False indicates that the module did not modify the target machine.

system_info contains the collected system information.

7.8 Handle Module Errors

Python 
module.fail_json(
    msg="Failed to collect system information: {}".format(error)
)

If an error occurs while collecting system information, fail_json() returns a failure response to Ansible.

8. Validate the Python Module

Before executing the module, validate the Python syntax.

Ansible Controller 
python3 -m py_compile library/ubuntu_system_info.py

If there are no syntax errors, the command completes without displaying an error message.

9. Create the Ansible Playbook

Now we need a playbook to execute the custom module.

Create a YAML file named ubuntu_system_info.yaml.

Ansible Controller 
cat > ubuntu_system_info.yaml <<'EOF'
---
- name: Run Ubuntu System Information Custom Module
  hosts: ansible-client
  become: true
  gather_facts: false

  tasks:

    - name: Collect Ubuntu system information
      ubuntu_system_info:
      register: result

    - name: Display system information
      debug:
        var: result.system_info

EOF

Understanding the Playbook

Parameter Explanation
name Describes the playbook.
hosts Specifies the target Ansible Client.
become Enables privilege escalation.
gather_facts Disables automatic fact gathering.
ubuntu_system_info Calls our custom Python module.
register Stores the module result in a variable.
debug Displays the collected information.
How does Ansible find the module?

Ansible searches for custom modules in the local library directory alongside the playbook.

Therefore, the module can be called directly using ubuntu_system_info: without specifying its Python filename or module path.

10. Execute the Custom Module

Navigate to the project directory on the Ansible Controller.

Terminal 
cd ~/ansible-custom-module

Execute the playbook using the normal Ansible playbook command.

Execute Playbook 
ansible-playbook ubuntu_system_info.yaml

12. How Ansible Executes the Custom Module

When you execute:

Command 
ansible-playbook ubuntu_system_info.yaml

Several operations take place:

  1. Ansible reads the YAML playbook.
  2. Ansible identifies the target host.
  3. Ansible searches for the custom module in the library directory.
  4. Ansible prepares the module for execution on the managed node.
  5. Ansible establishes an SSH connection to the Ubuntu Client.
  6. The Python module executes on the Ubuntu Client.
  7. The module collects hostname, OS, CPU, memory, disk and IP information.
  8. The module returns a JSON result.
  9. Ansible receives the result and stores it in the registered variable.
  10. The debug task displays the collected information.
